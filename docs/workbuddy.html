在 WorkBuddy 中使用

把 kingdee-mcp 接进 WorkBuddy，用自然语言查 / 操作金蝶云星空

1

打开连接器配置文件

WorkBuddy 的 MCP 配置为用户级 ~/.workbuddy/mcp.json（Windows 实际路径为 C:\Users\你的用户名\.workbuddy\mcp.json）。用编辑器打开它；若文件不存在则新建。

2

填入 kingdee 连接器

在 mcpServers 中加入如下 kingdee 项（整体为 JSON，注意不要破坏其它已有的连接器）：

{
  "mcpServers": {
    "kingdee": {
      "command": "uvx",
      "args": ["kingdee-mcp"],
      "env": {
        "KINGDEE_SERVER_URL": "http://你的金蝶地址/k3cloud/",
        "KINGDEE_ACCT_ID": "你的账套ID",
        "KINGDEE_USERNAME": "金蝶账号",
        "KINGDEE_PASSWORD": "金蝶账号密码"
      }
    }
  }
}

四个环境变量说明：
KINGDEE_SERVER_URL：金蝶 WebAPI 站点地址，结尾带 /k3cloud/
KINGDEE_ACCT_ID：数据中心（账套）ID，登录页下拉账套时可见
KINGDEE_USERNAME / KINGDEE_PASSWORD：金蝶账号密码（采用 ValidateUser 登录，无需 AppID / AppSecret）

3

保存并「重新信任」连接器

WorkBuddy 不会热重载 mcp.json。改完配置后，打开连接器管理页，找到 kingdee 这一项，点击「重新信任 / 重启」，让它以新配置重新派生进程。

⚠️ 如果只改文件不重新信任，WorkBuddy 仍会跑旧进程（旧地址 / 旧账号），表现为查不到数据或登录失败。

4

在对话框里直接说就行

信任成功后，新建一个任务，用自然语言描述你要做的事，例如：

  • 「查询最近 20 条已审核的销售订单」
  • 「导出 2020 年 2 月 001 账簿的科目余额表」
  • 「查物料 MAT001 的即时库存」
  • 「帮我新建一张采购订单，供应商 S001，物料 MAT001，数量 100」

查询类操作可以直接放心用；写操作（新建 / 审核 / 反审核 / 删除）建议先在测试账套验证，或让 AI 先把将要执行的参数展示给你确认。

排障小贴士

① 返回 0 行不一定是工具坏了：例如科目余额表选了账套里没有数据的期间（账簿 001 仅含 2020 年数据），会合法返回 0 行。

② 账号权限异常常被包成通用报错：若账号缺少对应模块（如财务报表）的操作权限，查询可能返回 Unknown Error 而非明确权限提示，需在金蝶里给账号授权。

③ 报表查询只支持简单账表：明细账、多账簿明细账等复杂账表接口会提示「此接口只支持简单账表!」。
